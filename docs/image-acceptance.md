# 镜像验收

在 GitHub 原生运行器上验收全部 30 个镜像，不下载到开发机测试。对象必须是实际导出后重新导入的镜像。

## 必须通过

| 项目 | 条件 |
|---|---|
| 产物 | 单规格名称、摘要、校验和及完整导出文件匹配 |
| 系统 | 对应原生架构可导入启动，发行版和版本正确 |
| 软件 | 包数据库确认 9 个预装包，CA 证书文件非空 |
| 说明 | 镜像说明包含准确的 `vpsm91.com` 内容 |
| 凭据 | 设置测试密码前，root 密码字段精确为 `!` |
| 残留 | 无账户备份、root 私人 SSH 状态及历史；检查只读，不现场修复 |
| 双栈 | 非链路本地 IPv6 与 IPv4 均能分别通过 `ssh -6`、`ssh -4` 登录 |
| 重启 | 重新获取地址后，两种地址族仍能登录，SSH 配置有效 |
| 身份 | 同一实例重启身份不变；同镜像两个独立实例的 machine-id 和每种 SSH 公钥均不同 |

## 执行顺序

构建导出 → 启用内网 IPv6 → 校验并重导入 → 系统与残留检查 → 设置临时密码 → 双栈登录 → 重启复测 → 第二实例双栈与身份对比 → 清理验收资源 → 上传报告。

验收失败不上传镜像。密码仅通过标准输入和受控进程环境传递，不写入日志、报告或原始产物；身份只记录摘要。

## 清理范围

- 清理 shadow、gshadow、passwd、group 的账户备份及对应备份目录条目，保留实际数据库。
- 清理 root 测试状态、历史以及临时目录内容，包含隐藏文件。
- 停止 SSH 后移除构建密钥，停止容器后清空 machine-id；首次启动生成缺失身份。
- 验收后只删除本次创建的项目资源，不操作共享网络和存储池。

## 输出与边界

- 任务日志和摘要逐项显示结果，报告保存在 `acceptance-*` 产物中，保留 7 天。
- 报告与镜像文件分开；超时、缺包、单栈登录失败或身份重复均判失败。
- 内网双栈通过不代表公网 IPv6 可达，不以外网域名解析或 HTTPS6 作为门槛。
- 启动后残留检查不等于原始归档全面扫描，不包含漏洞扫描、签名或软件物料清单。
- 新清理及身份初始化流程须由对应提交的远程运行证明，旧产物不自动更新。
